# Draft-контракт подтверждения применения позы

`tools/beholder_dogleg_pose_receipt.py` — **не выполненный и не проверенный исходник** следующего building block. Он не импортировался и не запускался на этом шаге. Тесты, PIE, компиляция, dry-run и вызовы функций не выполнялись; ассеты не менялись.

## Назначение

Числовые targets сами по себе не доказывают, что компоненты приняли позу. `PoseReceiptLedger` описывает локальный протокол:

1. Привязать numeric pipeline к исходной позе и неизменяемым world/actor/owner-epoch/geometry идентификаторам.
2. Получить свежий набор числовых целей из того же pipeline и before-снимок actual pose.
3. Выдать **описание предложения**, не команду, с transaction ID и ожидаемой следующей application revision.
4. До следующего предложения потребовать новый after-снимок: ровно одна application revision, более свежие probe/capture counters, те же identity/root/tip/contact и соответствие всех секций/суставов предложенной позе.

Повторный/старый receipt, продвижение numeric pipeline до подтверждения, смена источника job или несовпадение данных должны переводить **локальный протокол** в held. Pending очищается, pipeline также получает local held; штатного reset для продолжения нет. Это **не CancelStageRedistribution, не остановка актора и не физическое удержание**.

Последующая source-only доработка: ledger самостоятельно сопоставляет порядок предложений с **последним подтверждённым** образцом. Внутри сегмента время не убывает; переход допускается только в соседний сегмент, после receipt его предшественника в точном конце и с новым предложением в elapsed=0. Так отдельное использование ledger не должно пропускать подтверждения clamp-kink/разворота за счёт предварительного вычисления границ одним pipeline. Начальное предложение по-прежнему требует segment=0/elapsed=0. Изменение не исполнялось и не проверялось тестами; оно не устанавливает частоту измерений внутри сегмента или достоверность переданных снимков.

## Данные и границы доверия

`PoseEvidence` содержит frozen копии actual stage positions, relative sleeve translations, pitch/yaw/**roll** соединений, root/tip frames, live contact point и положения когтей/века. Все десять offsets/rotations обязательны. До/после чтения ожидаются совпадающие stamps; скалярные значения конечны, quaternion должен быть единичным без автоматической нормализации. При сравнении учитывается равнозначность q и −q.

Сопоставление sleeve translation использует прежний `STROKE*stage` в local см. Исходная поза должна соответствовать sequential E и нулевым изгибам. На всём предложенном цикле ожидаются фиксированные root и tip frames, контакт и закрытые когти/веко. Это узкий draft-контракт прежней геометрической модели, не произвольный режим глаза или ролей лап.

**Источника этих измерений в UE пока нет.** `application_revision` — проектируемый счётчик завершённых атомарных применений будущего единственного executor, **не** текущий engine frame counter и не готовая Blueprint-переменная. `probe_revision` и `capture_sequence` также не следует выдумывать/проставлять Python-кодом ради принятия receipt. Их будущий native capture должен реально связывать завершённое применение, свежий контакт и coherent read. Owner/geometry строки проверяют лишь неизменность переданных данных; они не захватывают настоящую блокировку и не удостоверяют достоверность геометрии.

Поэтому предложение и receipt всегда сохраняют `motionAuthorized=false`, `runtimeReady=false`, `actualPoseConfirmed=false`. Результат `suppliedPoseEvidenceCompared=true` означает только сравнение **переданных данных**, не аутентифицированное подтверждение актора. Напрямую посылать предложение в motion API нельзя.

## Предложенные сравнения, пока без верификации

В исходнике заданы draft tolerances: stage/joint 1e−6, sleeve translation 1e−4 local см, root position 0.001 world см, tip/contact 0.01 world см, scale 1e−6, quaternion chord 1e−8. Это параметры сравнения данных, **не новые утверждённые настройки физики/контакта** и не изменение guards работающего стенда. Совместимость actual component frames, Euler convention, ControlRig freshness и UE float не проверена.

Отсутствуют: UE adapter/capture, настоящий command-owner arbitration, atomic apply, rollback при частичном применении, native cancel/hold, игровые часы/тайм-ауты, live geometry admission, collision/force/support certificate. Исторический observer-блокер остаётся открытым. Сначала нужно отдельно разрешить и выполнить проверки числовых функций и протокола; этот код не включает движение.
