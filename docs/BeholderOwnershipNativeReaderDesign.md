Возврат nullptr helper не считать доказательством отсутствия сохранённых records. Ничего не включать в config автоматически.

### Raw parent reflection: кандидат, ещё не полностью проверенный primitive

`CoreUObject/Public/UObject/UnrealType.h:2625` объявляет GetObjectPropertyValue_InContainer(const void*, index) const; `CoreUObject/Private/UObject/PropertyObject.cpp:405–409` передаёт чтение в GetWrappedUObjectPtrValues<FObjectPtr>. Это подтверждает const-container API, **но не отсутствие lazy object resolution** в нижнем слое.

Кандидат алгоритма для MemberParent: найти именно FObjectProperty по точному reflected имени в FMemberReference::StaticStruct, проверить expected field type; прочитать из const адреса reference, затем записать null либо object path. Не вызывать property getter metadata, ResolveMember или SetPropertyFlags. Пока GetWrappedUObjectPtrValues/object-handle semantics не проверены, zero-mutation guarantee для этого шага не заявлять. При unresolved handle/невозможности safely получить path возвращать unsupported, не LoadObject. Поле bWasDeprecated требует аналогичного typed bool storage read; до source review тоже unsupported.

Эти уточнения получены чтением installed engine source, без выполнения primitive, компиляции или editor probe. Не считать расширение дизайна готовностью устанавливать reader.

- Запрос: точный allowlist из inspector plan; лимиты graphs/nodes/depth/bytes. Не разрешать произвольные property writes или function invocations.
- Preconditions: edit mode, не PIE/compile; assets уже загружены либо отдельно согласован loading scope. Asset loading может вызывать PostLoad, поэтому строгий read-intent reader не должен молча загружать всё дерево зависимостей.
- Выполнение на editor game thread; читать собственные graph arrays и вложенные BoundGraph с visited set. Точные Blueprint/graph/rig traversal primitives остаются на source review — не обещать rig coverage обычным K2 traversal.
- Результат: raw records + per-field errors + coverage/limits; null отличается от unsupported. Копировать значения в DTO, не отдавать изменяемые engine references клиенту.
- Для drift: package dirty/revisions до/после, если подтверждён read primitive. Отсутствие dirty change не доказывает отсутствие всех in-memory mutation. Не обещать atomic snapshot без соответствующего механизма.
- Если имеется unsupported/truncation/drift — вернуть partial/incomplete, без repair/retry с mutation. Никакого автоматического admission к reparent.
- Архивирование в новый UUID JSON может быть отдельным host-side шагом; сохранение JSON не равно SavePackage. По возможности reader возвращает DTO, а не пишет assets/clipboard.

## Рубеж следующего согласования

### Source-review текущей заготовки (без запуска)

- Проверены объявления VariableReference/FunctionReference и scalar accessors локального UE5.6; Package::IsDirty прямо возвращает bDirty. Это сверка source, не C++ compilation acceptance.
- Ранние отказы возвращают bAccepted=false, bComplete=false; owner/package identity проверяются до member extraction. Wrong-thread отказ предшествует доступу к GEditor/Node.
- При post-read state drift partial DTO сохраняется, bAccepted снимается; batch останавливается на таком node. ProcessedNodes включает rejected final record; оставшийся suffix не прочитан.
- Пустой Members не утверждает отсутствие bindings: other_node_references остаётся NotCaptured. Неопределённый WasDeprecated не подменяется false; invalid/zero GUID пока только raw observation, не автоматически corruption.
- Нет handler/endpoint/caller, LoadObject, CDO invocation, object-member resolution, asset save/compile или graph mutation. Отсутствие вызовов не является доказательством отсутствия всех косвенных engine effects при будущем запуске.
- Raw pointer вход должен быть живым и принадлежать удерживаемым caller objects: IsValid не делает произвольный dangling address безопасным. Caller/GC lifetime protocol ещё не реализованы. Не добавлять transport, принимающий адрес от клиента.
- Общий output byte budget отсутствует: bounded node count/expression не ограничивают Scope/path strings целиком. До transport/serialization нужен общий бюджет с явным truncation/error, а не молчаливое обрезание.
- Полные object references, BoundGraph traversal, pins/overrides/rig/revisions и recovery отсутствуют; это всё ещё scalar helper, а не готовый binding inspector. Проверка compile queue/GC/saving transitions в целом также не реализована.

**Итог:** подготовленный source требует отдельно согласованной compile verification и дальнейшего scope для full capture. Подключать его к reparent admission или объявлять готовым native snapshot нельзя. Tests/build/install/editor run этим review не разрешены и не выполнялись.

### Закрытая source-проверка lazy-resolution риска

`UnrealType.h:2669–2722` показывает: GetWrappedUObjectPtrValues при InContainer/HasGetter может вызвать getter, иначе переходит к GetObjectPropertyValue. `PropertyObject.cpp:395–398` последний вызывает `GetPropertyValue(...).Get()`. `ObjectPtr.h:112–114` FObjectPtr::Get вызывает **ResolveObjectHandle**. Следовательно, обычный object property getter не подходит как безусловно no-resolve primitive. Даже const API не гарантирует отсутствие resolution/cache effects.

Дизайн strict reader: проверять HasGetter и не вызывать getter; читать typed stored object-pointer wrapper через подтверждённый direct-storage accessor, проверять IsResolved **до** Get/path. Для unresolved record писать status=unresolved/notCaptured, без resolve/load и без заявления complete. ObjectPtr.h:192 и TObjectPtr::IsResolved:743–745 подтверждают наличие проверки resolved state. Конкретный direct-storage typed extraction ещё требует review; unsafe casts, private NoRead/NoCheck APIs и изменение flags не предлагаются как shortcut.

То же ограничение распространяется на traversal TObjectPtr arrays/BoundGraph/handler/template/parent fields: защитить только MemberParent недостаточно. Любой implicit pointer conversion перед IsResolved нарушает strict-reader policy. Read callbacks/GC effects и полный no-side-effect runtime результат этим source анализом не проверены.

**Практический stop-point подготовки:** базовые риски определены; ещё один JSON с display names не закроет bindings. Для дальнейшей реализации требуется явный scope изменения исходников reader. Plugin patch/build/install/editor run и reparent не выполнялись. Допустимый следующий отдельно согласуемый шаг — только source patch узкого native DTO reader с incomplete/unresolved handling, без регистрации исполняемого endpoint до review; build/run остаются запрещены до отдельного разрешения.

Сначала закрыть source review raw struct reflection, traversal и loader/dirty semantics. Затем отдельно согласовать ограниченные plugin source changes. Build/install/restart/editor execution/tests/compile assets/reparent — разные разрешения; их нельзя подразумевать разрешением подготовить дизайн. До реализации пригодный полный binding snapshot отсутствует, recovery policy остаётся открыта.
