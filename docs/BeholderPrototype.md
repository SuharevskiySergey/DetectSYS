# Прототип бехолдера: этап I

## Что действительно готово

Ассет: `/Game/BeholderPrototype/BP_BeholderEye_Prototype`.
Материалы: `/Game/BeholderPrototype/Materials/`.
Демо: `BeholderEye_Demo` на `/Game/ThirdPerson/Lvl_ThirdPerson`, координаты `(0, 350, 150)` см.

Это технический модуль глаза, **не готовый бехолдер и не законченный этап I** из `Task.md`. Исходные эксперименты в `Content/Bluprient/` не изменены.

Для навершия на самой лапе теперь используется отдельный `BP_Lapa5_Head` на основе пользовательской модели ЛАПА5: см. `Lapa5Head.md`. Данный документ описывает оставленный для сравнения первоначальный прототип со сферами и конусами.

- Глаз и наружная оболочка — отдельные сферы; впереди радужка и зрачок.
- Три когтя постоянно прикреплены к своим `ClawPivot0..2`, а те — к `EyeRoot`.
- Плоскости движения разнесены на 120°. Локальная ось взгляда — **+Z**; независимого поворота глазного яблока нет.
- Диапазон хода каждого когтя — 90°: относительный Pitch от `36.83` (закрыт) до `-53.17` (открыт). Это угол шарнира прототипа, не абсолютный угол раскрытия из ТЗ.
- Веко раскрывается независимо от индивидуального переопределения когтей.
- Материалы неметаллические. Вложение глаза/радужки в оболочку намеренное; соответствующие компоненты помечены `mcp.placement.ok`.

## Параметры экземпляра

| Параметр | Значение / назначение |
|---|---|
| `TargetOpening` | Целевое раскрытие 0–1, когда `bAutoDemo=false` |
| `TransitionSeconds` | Время полного хода 0→1; по умолчанию 0.8 с, технический параметр, не утверждённый баланс |
| `Claw0Override..Claw2Override` | Отрицательное значение: следовать общему раскрытию; 0–1: независимый угол |
| `bAutoDemo` | По умолчанию false в классе; true только у демонстрационного экземпляра |
| `CycleSeconds` | Полный демонстрационный цикл; по умолчанию 4 с |

`Opening` и `Elapsed` — внутреннее состояние. Общий ход обновляется с учётом DeltaSeconds через `FInterpTo_Constant`. Период демо ограничен снизу 0.1 с, время перехода — 0.01 с для защиты деления. При слишком коротком цикле фактическое раскрытие может не успеть достигнуть цели.

## Интерфейс Blueprint

- `SetEyeOpening(Amount: float)`: ограничивает цель диапазоном 0–1 и выключает `bAutoDemo`, чтобы ручная команда не перезаписывалась демонстрацией.
- `SetClawOpening(ClawIndex: int, Amount: float)`: индекс 0–2. Значение <0 возвращает общий режим; иначе угол ограничивается диапазоном 0–1. Неизвестный индекс ничего не меняет.
- Переопределение отдельного когтя применяется непосредственно, без отдельной интерполяции. Это управление позой, **не реализованный режущий удар** с уроном, траекторией и запретом отмены.

Для быстрого просмотра откройте карту и нажмите Play: демонстрационный глаз циклически раскрывается. Изменения свойств/вызовы функций в Play относятся только к игровому экземпляру и исчезают при Stop.

## Проверки, выполненные через EngineWire в Play

1. Запуск демо: `Elapsed` увеличивается, `Opening` меняется; `bAutoDemo=true`.
2. `SetEyeOpening(1)`: после перехода `TargetOpening=1`, `Opening=1`, `bAutoDemo=false`; Pitch первого когтя `-53.17°`.
3. `SetClawOpening(0, 0)` при открытом глазе: `Opening=1`, Pitch первого когтя `36.83°`, остальных `-53.17°`; Yaw остальных `120°` / `-120°`. Связь шарниров с `EyeRoot` сохраняется.
4. `SetClawOpening(0, -1)`: `Claw0Override=-1`, возвращается общее управление.
5. `SetClawOpening(99, 1)`: после вызова переопределения всех трёх когтей остаются `-1`.
6. `SetEyeOpening(-2)`: после перехода `TargetOpening=0`, `Opening=0`, Pitch первого когтя `36.83°`.
7. Blueprint и пять материалов компилируются без ошибок; проверка графа не возвращает предупреждений. Play остановлен, уровень сохранён.

Это проверка состояния и трансформов, **не визуальная приёмка** формы века, кончиков когтей и пересечений во всех промежуточных позах.

## Ограничения и следующий этап

- Оболочка открывается маской `M_EyeLid_Prototype` по UV стандартной Engine Sphere, а не Morph Targets / костями. Это визуальная заглушка без толщины и органического края; при замене сетки материал требует переработки.
- Когти — конусы на SceneComponent-шарнирах, не финальные органические меши на костях. Коллизии визуальных частей отключены; опора, режущий контакт, защита глаза от земли и урон не реализованы.
- Начат отдельный прототип изгиба одной лапы: `docs/BeholderLegPrototype.md`. Телескопии, тела с восемью гнёздами, ходьбы, лазания, лучей, антимагии, восприятия, здоровья и регенерации ещё нет.
- Перед завершением этапа I нужны художественная геометрия, костный риг и деформация оболочки, затем визуальная проверка закрытой пирамиды, раскрытия и независимого режущего хода.
- Для этапа II можно использовать существующую цепочку `CR_Tenticle` (Hip → Knee01..08 → Foot → Foot_end). В исходном `BP_Tenticle` узлы `Add Mapped Skeletal Mesh` и `Set Control Position` не подключены к исполнению, а `SKM_Tenticle.AnimClass=None`; исправлять и проверять на отдельной копии, не считать эту лапу готовой.
