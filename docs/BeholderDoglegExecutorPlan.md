Это заготовка числовой функции, а не runtime-исполнитель. Открытый исторический assertion остаётся в `Task.md`; движение dogleg/IK не разрешено.

## Контракт установленной функции

`CalculateDoglegTargets` — функция отдельной Blueprint Function Library, с exec-входом, но **без изменения состояния**. Она возвращает один набор числовых целей. Exec/Branch используются для явного отказа по невалидным аргументам, а не для управления секциями.

Входы:

| Вход | Диапазон/смысл |
|---|---|
| BaseExtension | исходное sequential-выдвижение E, 0.4…0.9 |
| Phase | геометрическая доля изгиба f, 0…1; **не секунды** |
| AmplitudeDegrees | знаковая амплитуда A, −1…1° |
| UseYaw | true — только yaw, false — только pitch |

Ordered range checks должны отвергать NaN/Inf; поведение с реальными UE float-пинами ещё не проверено. Ввод не зажимается до разрешённых диапазонов, чтобы недопустимый запрос не выдавался за принятый.

Выходы:

- `NumericInputsAccepted` — прошли **только числовые** условия;
- `MotionAuthorized` — **всегда false**, включая численно допустимый результат;
- `CompensatedExtension`, десять `Stage0Target`…`Stage9Target`;
- pitch/yaw targets всех девяти соединений. Неиспользуемая ось и соединения 4…9 явно получают нули; три активных соединения получают α/−2α/α. Корень не перемещается и не поворачивается.

Формулы перенесены из прежней идеальной dogleg-модели:

```text
α = A*f
E' = E + 4*sin²(α*pi/360)/10
Stage[i] = clamp(10*E' − i, 0, 1)
Joint[1,2,3] = α, −2α, α на одной выбранной оси
```

При численном отказе отдельный return возвращает false и нули во всех числовых выходах. **Эти нули нельзя применять к лапе**: они означают отсутствие принятого набора, а не команду втягивания. Возвращённое E' может немного превышать 0.9 при исходном E=0.9; его нельзя передавать старому redistribution API как обычный допустимый запрос.

## Чего заготовка не делает

- Не читает актор, контакты или геометрию; не проверяет исходную sequential-позу, прямизну, когти и владение контроллером.
- Не хранит часы/фазу, не проигрывает quintic-профиль и не проверяет скорости/ускорения.
- Не вызывает `SetJointBend`, stage setters, transform setters, Tick или IK.
- Не переносит старые spatial bounds на произвольные входные/фактические позы.
- Не делает физическую поддержку, ходьбу или аварийный останов.

Один вызов для получения числового набора **не доказывает синхронное применение** этого набора компонентам. Будущий единственный владелец движения должен захватить фиксированный root/contact frame, валидировать actual pose и live geometry, исключить конкурирующие команды, вычислять все цели из одной фазы, применять связанный набор и подтверждать actual pose после обновления. Частичный отказ применения не должен оставлять неконтролируемое движение.

## Сегментный clock — установлен, только компиляция

Изначально после выбора пользователя **«Продолжать без проверок»** подготовлен только исходник `tools/build_beholder_dogleg_clock_graph.py`. Позже получено **отдельное явное разрешение «Создать и скомпилировать»** именно для clock: создана и сохранена Function Library `/Game/BeholderPrototype/Telescopic/BP_BeholderDoglegClock` с `EvaluateDoglegSegment`. Сначала создана сигнатура, затем установлены 92 операции тела графа; compilerStatus=UpToDate, **0 ошибок / 0 предупреждений**.

**Функцию не вызывали.** Числовые результаты, производные, NaN/границы и совместимость UE float не проверялись; тесты/PIE/dry-run не выполнялись. Граф не подключён к targets, акторам, игровым часам или движению. План теперь уже установлен и **неидемпотентен**, повторно не применять к существующему ассету. Предыдущее разрешение на эту компиляцию не разрешает последующие вызовы или тесты.

Функция предназначена только для вычисления общей фазы на одном уже запланированном quintic-сегменте. Входы — elapsed от начала сегмента, его duration, геометрические границы PhaseStart/PhaseEnd и Returning. На обоих направлениях локальное elapsed возрастает от 0 к duration. Нормированная форма `q(u)=10u³−15u⁴+6u⁵` вычисляется симметрично через `min(u,1−u)`, как в прежнем Python timing. Возвращаются фаза, её скорость/ускорение и SegmentComplete. `MotionAuthorized` остаётся false; при численном отказе все числовые выходы нулевые и SegmentComplete=false. Отказные нули нельзя применять к лапе.

Для прямого сегмента `f=lo+(hi−lo)*q(u)`, для обратного `f=hi−(hi−lo)*q(u)`. В **этой форме** обратного хода обе производные получают минус, потому что u возрастает по времени возврата. Это эквивалентно прежнему отражению времени: там вторая производная имеет положительный chain-rule множитель, но вычисляется в отражённой точке q''(1−u)=−q''(u). Эта эквивалентность пока описана в коде, **а не подтверждена запуском новой Blueprint-функции**.

Предложенные ordered numeric guards требуют `0≤elapsed≤duration≤60`, `0≤lo<hi≤1`. Нижняя граница duration **1e−6 с** — консервативный арифметический порог, не утверждённый профиль движения или физическое ограничение. Очень короткие сегменты прежнего планировщика могут быть отвергнуты; до runtime-использования необходимо отдельно согласовать и проверить совместимость представления UE float с сегментами у clamp-kink.

Это **не сам планировщик сегментов**: функция не вставляет clamp-kink stops, не выбирает sqrt-span длительности, не проверяет скорость суставов/секций, не читает игровые часы и не хранит состояние. Границы и длительности должен выдавать отдельный принятый job-план. Она также не вызывает установленный `CalculateDoglegTargets`. Будущий единственный владелец движения должен передавать одну вычисленную фазу этому калькулятору; независимые joint/stage интерполяторы не становятся допустимыми от наличия clock-функции.

В этой библиотеке нет Tick, setters, transform-команд, таймеров или включения движения. Выполнена только отдельно разрешённая компиляция; тесты/PIE/dry-run и вызовы функции не выполнялись, новые тесты не добавлены. Исторический observer-блокер и отсутствие проверенного синхронного исполнителя сохраняются.

## Подготовленный пакет задания — также без запуска

Добавлены исходники `tools/beholder_dogleg_job.py` и `tools/beholder_dogleg_job_contract.py`. **Они не выполнялись и не проверялись**. Это подготовка данных для будущего единственного владельца движения, не работающий исполнитель и не новое разрешение запускать функции в Unreal.

`prepare_job` предназначен для построения frozen job/segment объектов из прежнего `DoglegTiming`: outward-сегменты сохраняют clamp-kink границы и sqrt-span длительности, return-сегменты идут в обратном порядке с общими зеркальными временными границами. Проверки в исходнике требуют непрерывности времени/фазы и возврата в фазу 0. Код пересчитывает reference velocity/acceleration bounds по фактически сохранённым длительностям обеих половин, а не предполагает точное совпадение floating-point разностей после отражения. Эти проверки **ещё не запускались** и не являются новым результатом верификации.

`half_duration=None` запрашивает прежний reference-budget fit; явная длительность остаётся явной. Предложенные арифметические границы duration вынесены в общий contract и используются clock-планом и job-кодом. Сегмент короче 1e−6 с должен отвергаться, **не склеиваться через clamp-kink** и не растягиваться незаметно. Совместимость с UE float, минимальные spans и чувствительность budgets на отражённых границах по-прежнему требуют отдельного разрешения на проверки.

Методы `clock_arguments` и `target_arguments` формируют **только словари аргументов**, без вызовов калькуляторов. `to_dict` создаёт отдельные контейнеры с schemaVersion=1, временными сегментами, reference bounds и binding-именами; исходный frozen job ими не изменяется. Пакет явно содержит `status=draft_unverified`, `runtimeReady=false`, `runtimeTimingCertified=false`, `runtimeIKExecuted=false`, `motionAuthorized=false`. Это описание задания, не готовый payload для прямой отправки в MCP и не утверждение физической допустимости.

В пакете перечислены незакрытые gates: числовая проверка targets и clock, live admission фактической позы/контакта, эксклюзивное владение командами, синхронное применение с подтверждением actual pose, разрешение исторического observer-блокера. Установка clock уже завершена, но его числовая проверка остаётся незакрытой. Root/contact snapshot, арбитраж контроллеров, часы, cancel/hold и запись компонент job-кодом **не реализуются**.

## Подготовленная связка clock → targets — только числовой протокол

Добавлен исходник `tools/beholder_dogleg_pipeline.py`, **не выполненный и не проверенный**. `DoglegCalculationPipeline` формирует запрос данных к clock, принимает именованный числовой ответ, затем формирует запрос к targets **с той же фазой**. Метод формирования запроса не вызывает Unreal, а возврат `NumericPoseSample` не означает применения позы.

В заготовке предусмотрены один pending request, идентификатор сессии/номера/стадии расчёта, запрет повторных и перепутанных ответов. Новый образец начинается только из первого сегмента в elapsed=0; время внутри сегмента не убывает, следующий сегмент требует сначала расчёт конца предыдущего, затем собственного начала. Так numerical pipeline не должен незаметно перескакивать через clamp-kink/разворот. Это **не** арбитраж actual controllers и не per-frame гарантии применения.

Код предусматривает отклонение отказных/неполных/нечисловых ответов и неожиданного MotionAuthorized, сравнение clock с прежним quintic и targets с прежней dogleg-моделью, включая нули остальных суставов. Предложенные допуски числового сравнения: absolute 1e−6, для производных дополнительно relative 1e−5. **Они не проверены с UE float**, особенно для коротких сегментов; это не изменение существующих геометрических/contact/controller guards и не разрешение переносить bounds точной кинематики на приближённую позу.

Любой предусмотренный protocol reject переводит **локальный числовой конвейер** в held и очищает pending/candidate/sample; штатного reset из held нет. Это не вызов Cancel, не остановка движения и не физическое удержание. Текущие расчётные пакеты всегда помечены calculationOnly=true/motionAuthorized=false; samples также actualPoseConfirmed=false/runtimeReady=false.

Адаптер именованных UE outputs, реальные вызовы калькуляторов, владение лапой, live admission, root/contact snapshots, часы, actual-pose acknowledgement и actuator writes отсутствуют. Pipeline нельзя подключать напрямую к движению или считать готовым исполнителем. Исходник не импортировался/не запускался нами на этом шаге; тесты/PIE/dry-run/компиляция и вызовы UE-функций не выполнялись, новых ассетов и тестов нет.
