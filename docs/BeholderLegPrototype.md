# Прототип одной лапы: начало этапа II

Отдельный образец с реальным вложением десяти жёстких полых секций, навершием ЛАПА5 и малым ограниченным изгибом описан в `BeholderTelescopicPrototype.md`. Он не заменяет эту сплайновую лапу.

## Ассеты и изоляция

Все новые ассеты находятся в `/Game/BeholderPrototype/`:

- `BP_BeholderLeg_Prototype`: копия `BP_Tenticle` (родитель Pawn), с новым графом управления ригом.
- `CR_BeholderLeg_Prototype`: копия `CR_Tenticle`, оставлены восемь узлов рабочего сплайнового решателя; несвязанные экспериментальные ветки удалены только из копии.
- `SKM_BeholderLeg_Prototype` и `SKEL_BeholderLeg_Prototype`: копии меша и скелета. Меш использует новый скелет; источник не менялся.

Оригинальные ассеты из `Content/Bluprient/New_Beh/BP_TRY_Stend/Tentecle/` сохранены без изменений. Старые функции поиска опоры в копии BP оставлены для справки, но новый EventGraph их не вызывает; отключённые узлы Clear удалены из копии `Get_Perfect_Pos`. Это не готовый планировщик шага.

## Как посмотреть

На `/Game/ThirdPerson/Lvl_ThirdPerson` добавлен **`BeholderLeg_Demo`**:
позиция `(-500, 650, 350)` см, масштаб `(0.25, 0.25, 0.25)`, папка Outliner `BeholderPrototype`.
Нажмите Play: конец лапы движется в пространстве, середина цепочки изгибается.

Прикреплённое навершие ЛАПА5 теперь автоматически открывается/закрывается каждые 4 с (`bHeadDemo=true` только у демо). У отдельного когтя есть плавный ход 0.4 с; параметры и команды перечислены в `Lapa5Head.md`.

Для фиксированной цели перед Play выключите `bAutoDemo` у экземпляра и задайте `TargetLocal`. Для другой формы изгиба меняйте `BendOffset`. Демонстрация подвешена намеренно (`mcp.placement.ok`); физическая опора и столкновения не реализованы.

| Параметр | Назначение |
|---|---|
| `TargetLocal` | Цель в пространстве компонента ControlRig, в см до масштаба экземпляра; по умолчанию `(800, 0, -200)` |
| `LiveTargetLocal` | Идеальная конечная цель после демо, ограничения расстояния и применения ExtensionPosition |
| `SolverTargetLocal` | Фактическая конечная точка сплайна; около основания сохраняет минимальную длину 1 см в пространстве рига |
| `RequestedTargetLocal` | Запрошенная цель текущего обновления с учётом демо, до ограничения |
| `RequestedTargetDistance` | Длина RequestedTargetLocal, для диагностики |
| `MaxTargetDistance` | Максимальная дистанция цели от начала рига; по умолчанию 1040 см в пространстве рига, эффективное значение не меньше 1 |
| `bTargetDistanceClamped` | true, если в текущем обновлении запрос длиннее эффективного MaxTargetDistance |
| `ExtensionAmount` | Независимая команда выдвижения 0–1; по умолчанию 1 |
| `ExtensionPosition` | Текущее плавное выдвижение 0–1, изначально 1 |
| `ExtensionTransitionSeconds` | Время полного хода 0↔1, по умолчанию 0.6 с, минимум 0.01 с |
| `LiveTargetDistance` | Длина идеальной LiveTargetLocal |
| `BendFadeDistance` | Дистанция ослабления изгиба около основания, по умолчанию 200 см пространства рига |
| `LiveBendOffset` | Фактический изгиб после учёта выдвижения и близости к основанию |
| `bNearBaseFallback` | true при LiveTargetDistance < 1: решатель использует ненулевой запас вместо вырожденного сплайна |
| `SocketAxisLocal` | Ось посадки в пространстве рига, по умолчанию +X; используется направление, не длина вектора |
| `SocketAlignmentStart` | Доля выдвижения, ниже которой начинается выравнивание; по умолчанию 0.2, эффективно 0.01–1 |
| `bAlignRetractionToSocket` | Включает выравнивание при втягивании; по умолчанию true |
| `SocketAlignmentWeight` | Текущий вес выравнивания 0–1 |
| `SolverDirectionLocal` | Направление конечной точки сплайна после выравнивания |
| `BendOffset` | Смещение двух промежуточных точек, по умолчанию `(0, 0, 200)` |
| `bAutoDemo` | false в классе, true у демо-экземпляра |
| `DemoAmplitude` | Радиус кругового смещения цели в плоскости YZ, по умолчанию 100 см пространства рига |
| `CycleSeconds` | Период демо, по умолчанию 4 с, снизу ограничен 0.1 с |

Публичная функция **`SetTargetLocal(Position: Vector)`** задаёт цель и выключает демо. Мировая цель при нулевой ротации демо: `ActorLocation + 0.25 * Position`. Для произвольного трансформа нужно преобразовать позицию трансформом компонента ControlRig.

Теперь исходный `TargetLocal` сохраняет запрос, но при слишком большой дистанции **мировой целью будет преобразованный LiveTargetLocal**, а не исходный Position. Ограничение радиальное: направление сохраняется. Оно применяется каждый PreForwardsSolve после добавления демонстрационного смещения, поэтому защищает и ручные команды, и демо. Нулевой запрос остаётся нулевым. Это ограничение конечной точки, не общей длины изогнутого сплайна; произвольный BendOffset всё ещё может чрезмерно растягивать цепочку. Значение 1040 выбрано по сумме референсных длин, но не доказывает достижимость всех целей внутри сферы.

После добавления управления выдвижением `LiveTargetLocal = ClampVectorSize(RequestedTargetLocal, 0, max(MaxTargetDistance,1)) * ExtensionPosition`. На расстояниях меньше 1 см решателю передаётся **SolverTargetLocal**, а не нулевая LiveTargetLocal; подробнее ниже.

## Подключение и важные особенности

- `OnPreInitializeDelegate` вызывает `AddMappedCompleteSkeletalMesh` с направлением Output.
- `OnPreForwardsSolveDelegate` задаёт четыре `SetControlPosition` в **RigSpace**, перед решением рига. Нет зависимости от порядка Actor Tick и Component Tick.
- Точки: начало `(0,0,0)`, `SolverTargetLocal/3 + LiveBendOffset`, `2*SolverTargetLocal/3 + LiveBendOffset`, конец `SolverTargetLocal`. Переменная `ControlRigClass` ссылается на **копию** рига.
- Риг использует `Fit Chain on Spline Curve`, Alignment `Stretched`, SamplingPrecision `64`, и исходные оси костей. Это аппроксимация сплайна, не точный IK и не механическая модель телескопии.
- `bUpdateRigOnTick=true`, `bResetTransformBeforeTick=true`, lazy evaluation выключена. `AnimClass=None` намеренно: меш обновляет ControlRigComponent, второй AnimBP ему не нужен.
- При первичной проверке `Foot_end` в риге двигался, но в меше оставался в начале. В **копию скелета** добавлен сокет `EyeTip` на `Foot_end`, `bForceAlwaysAnimated=true`; после этого позиции меша и рига совпали. Не удалять сокет без повторной проверки конечной кости.
- Масштаб корневой кости `Hip` равен 100. У `EyeTip` RelativeScale `0.01` по каждой оси для компенсации масштаба кости. К сокету теперь прикреплён `HeadModule` с навершием из ЛАПА5; подключение и управление описаны в `Lapa5Head.md`.
- Для меша назначен неметаллический `M_Claw_Prototype`, вместо исходного WorldGridMaterial. При редактировании SCS следует проверять **SkeletalMeshAsset**, а не только устаревшее поле SkeletalMesh; уже размещённая копия может сохранить прежний меш. У демо и шаблона проверена ссылка на `SKM_BeholderLeg_Prototype`.

## Чего этот прототип НЕ делает

- В цепочке 11 костей, но не десять равных физических сегментов. С учётом масштаба Hip расстояния в референсной позе: примерно 40 см, восемь раз по 120 см, 40 см (всего 1040 см).
- Нет телескопического вложения оболочек и ограничения изгиба по степени выдвижения. Сжатие/растяжение позы по сплайну не заменяет эти требования.
- Есть только ограничение расстояния конечной цели. Нет ограничения полной длины сплайна, суставов, самопересечений, траектории движения или полной проверки достижимости; не использовать как физическую опору.
- Навершие на конце подключено (`Lapa5Head.md`); гнезда в теле, складывания внутрь сферы, контакта с поверхностью и распределения опор пока нет.

Следующий этап: согласовать/исправить длины сегментов на **копии модели**, реализовать отдельное управление выдвижением и изгибом с проверкой внешних пересечений. Лишь затем считать выполненной одну телескопическую лапу из `Task.md`.

## Раздельное выдвижение и изгиб; защита около основания

Добавлены команды:

- `SetLegExtension(Amount)` — ограничивает Amount до 0–1 и задаёт независимую цель выдвижения. Не меняет TargetLocal, BendOffset и режим демо. Переход через `FInterpTo_Constant`, поэтому смена команды в движении не телепортирует позу.
- `SetLegBendOffset(Position)` — меняет только запрос изгиба, не цель и не выдвижение. Отдельной интерполяции изгиба пока нет.

Эффективный изгиб вычисляется как:

```text
LiveBendOffset = BendOffset * ExtensionPosition
    * clamp((LiveTargetDistance - 1) / max(BendFadeDistance,1), 0,1)
    * (1 - SocketAlignmentWeight)
```

У самого основания он обращается в ноль. Это убирает прежнюю петлю, но нельзя передавать решателю четыре одинаковые нулевые точки: в диагностическом запуске при TargetLocal=BendOffset=0 он вернул референсную вытянутую цепь с промахом около 260 см. Поэтому SolverTargetLocal сохраняет длину минимум 1 см локально. Исходное направление берётся из запроса; при его длине меньше 0.0001 используется локальная +X. На последнем участке выдвижения направление теперь плавно заменяется осью гнезда (см. ниже). Это явная регуляризация решателя, **не точное попадание в ноль**.

Проверено после изменения при масштабе демо 0.25:

|---|---|---|
| `(0,0,0)` / 1 | SolverTargetLocal=`(1,0,0)`, изгиб 0 | 0.250 см вместо прежних 17.278 см |
| `(0.1,0,0)` / 1 | запас длины 1 см, изгиб 0 | 0.225 см |
| `(-1,0,0)` / 1 | направление −X сохранено, изгиб 0 | 0.000025 см |

| `(100,20,-20)` / 1 | плавно ослабленный изгиб | 0.470 см |
| `(800,200,-200)` / 1 | прежняя цель и изгиб 200 сохранены | 0.169 см |
| `(800,200,-200)` / 0.5 | цель `(400,100,-100)`, изгиб `(0,0,100)` | 0.085 см |

## Выравнивание по оси гнезда при втягивании

При `ExtensionPosition >= SocketAlignmentStart` направление не изменяется. Ниже порога вычисляется:

```text
t = clamp(1 - ExtensionPosition / clamp(SocketAlignmentStart,0.01,1), 0,1)
SocketAlignmentWeight = t*t*(3-2*t)  // или 0 при отключённой функции
```

Направление запроса и SocketAxisLocal переводятся в повороты через FindLookAtRotation, смешиваются RLerp с `bShortestPath=true`, затем GetForwardVector даёт единичный SolverDirectionLocal. Это избегает схлопывания линейной смеси противоположных векторов. Длина SolverTargetLocal остаётся `max(LiveTargetDistance,1)`; изгиб дополнительно ослабляется множителем `1-weight`. Нулевой SocketAxisLocal в текущей реализации FindLookAtRotation даёт +X; для гнезда задавайте явный ненулевой вектор. Настройки оси/порога меняйте до движения: отдельного ограничения скорости их изменения нет.

Исходный TargetLocal и идеальная LiveTargetLocal сохраняются: **во время посадки решатель намеренно отходит от прямого наведения**. Например, запрос `(0,800,0)` при выдвижении 0.1 имеет идеальную цель `(0,80,0)`, но SolverTargetLocal становится `(56.5685,56.5685,0)`. Расстояние EyeTip от идеальной цели около 15.31 см здесь не ошибка решателя: ошибка относительно точки посадочной траектории всего 0.0011 см. Проверочный скрипт отдельно возвращает `solverEndpointWithinOneCm` и `endpointWithinOneCm`.

Проверены статические позы в PIE для запроса вдоль +Y и оси гнезда +X:

| Выдвижение | Вес выравнивания | Направление SolverTargetLocal |
|---|---|---|
| 1 и 0.2 | 0 | +Y |
| 0.1 | 0.5 | `(0.707107,0.707107,0)` |
| 0.05 | 0.84375 | `(0.970031,0.242980,0)` |
| 0 | 1 | +X |

Дополнительно проверены противоположный запрос −X (в середине проходит через +Y, без нулевого вектора), другая ось гнезда +Y и отключение выравнивания. Во всех девяти статических случаях ошибка EyeTip относительно SolverTargetLocal была меньше 0.18 см. При полном втягивании измерено совпадение направления взгляда головы (её локальная +Z) с мировой осью гнезда: скалярное произведение 1.0, положение головы совпадает с EyeTip.

В динамическом тесте с временным `ExtensionTransitionSeconds=2` шесть последовательных измерений дали выдвижение `0.189537→0.128508` и вес `0.007925→0.291979`, с промежуточными направлениями без скачка. Это настройка только тестовой PIE-копии; после Stop сохранённое время полного хода снова 0.6 с. Регрессия обычного демо при ExtensionPosition=1 прошла: вес 0, ошибка конца около 0.179 см.

Снимок полностью втянутой и выровненной позы: `Saved/Screenshots/Beholder_socket_aligned_retracted.png`. Геометрии корпуса и самого гнезда пока нет; остаются наложенные сегменты и выступающий участок меша. Выравнивание не означает безопасную бесконтактную посадку, контроль осевого twist или завершённую телескопию. Команда `SetLegExtension(0)` запускает посадку; простая нулевая цель при ExtensionPosition=1 сама по себе не включает это выравнивание.
